# CSV to ClickHouse

Streamlit-приложение для загрузки CSV-файлов с сервера в новые таблицы
ClickHouse: локальную `ReplicatedMergeTree` и распределенную `Distributed`.

## Первый запуск за три шага

```cmd
git clone git@github.com:Odarink/csv_to_click.git
cd csv_to_click
loader.bat
```

`loader.bat` сам поставит окружение и откроет приложение; адрес он напечатает в
том же окне. Всё, что нужно на машине, — Python или `uv`: если `uv` не найден,
загрузчик поставит его сам тем Python, который найдёт, и продолжит.

Обновление — `git pull` в той же папке, затем снова `loader.bat`. Версию текущей
копии загрузчик печатает при запуске: короткий хеш и дата коммита. Её же стоит
назвать, если что-то пошло не так.

Загрузка выполняется через pandas chunks и `clickhouse-connect.raw_insert()` в
формате `JSONEachRow`. Этот путь выбран как основной, потому что в HTTP/proxy
окружениях `client.insert()` и `insert_df()` могут падать, а `JSONEachRow`
обычно проходит стабильно.

### Как сериализуются значения

Чанк целиком превращается в `JSONEachRow` одним вызовом `DataFrame.to_json`.
Построчного цикла нет: на замеренном профиле (одна колонка, 107 млн строк) он
занимал 90% времени вставки. Замер до/после — `benchmarks/serialize_bench.py`.

Два следствия этого выбора, которые стоит знать:

- **Дробные числа пишутся с точностью до 15 знаков после запятой.** Это потолок
  параметра `double_precision`. Значению, которому нужно 16–17 значащих цифр,
  срежет последнюю: `1/3` уходит как `0.333333333333333`. Относительная
  погрешность ~1e-16, то есть на границе представимости самого `Float64`.
  Минус ноль записывается как `0.0`.
- **`DateTime` уходит с пробелом, а не с `T`:** `2024-01-02 03:04:05`. Это
  канонический `basic`-формат ClickHouse; дробных секунд в нём нет.

## Требования

- `uv` — единственное, что нужно установить руками; Python он скачает сам
- доступ к ClickHouse
- CSV-файл должен лежать на той машине, где запущен Streamlit
- CSV должен содержать строку заголовков
- для secure-подключения нужны клиентские сертификат и ключ

Окружение ставится из `uv.lock` командой `uv sync --locked --extra dev` — это
единственный поддерживаемый способ запуска. Версии библиотек зафиксированы
намеренно: иначе `pandas`, `clickhouse-connect` или `urllib3` могут смениться
между двумя загрузками, и сравнение их времени перестаёт что-либо значить.
Флаг `--locked` выбран вместо `--frozen` осознанно: `--frozen` использует
локфайл, вообще не сверяя его с `pyproject.toml`, а `--locked` откажется
запускаться на разъехавшемся локфайле — молчаливое перерешивание как раз и есть
то, что делает прогоны несравнимыми. Версия интерпретатора закреплена в
`.python-version`, зависимости — в `pyproject.toml` и `uv.lock`.

Группа `dev` ставится вместе с рантаймом сознательно: `uv sync` по умолчанию
приводит окружение в точное соответствие локфайлу, то есть без `--extra dev`
каждый запуск `loader.bat` удалял бы `pytest` из того же `.venv`, которым
проверяется код. Побочный эффект: `pip` из `.venv` удаляется — он больше не
нужен, пакеты ставит `uv`.

## Локальный запуск на Windows

Откройте папку проекта и запустите `loader.bat`.

При первом запуске файл сам:

- перейдет в директорию проекта;
- найдет `uv`, а если его нет — поставит сам тем Python, который найдет на
  машине (`py -3.12 -m pip install --user uv`), и продолжит;
- поставит окружение из `uv.lock` командой `uv sync --locked --extra dev`
  (Python версии из `.python-version` `uv` при необходимости скачает сам);
- проверит, что доступны `streamlit`, `pandas` и `clickhouse_connect`;
- напечатает версию копии — короткий хеш и дату коммита;
- запустит приложение и напечатает адрес. Обычно это
  `http://127.0.0.1:8501`, но если порт занят другой копией, будет взят
  следующий свободный — смотрите напечатанную строку, а не привычный номер.

Загрузчик остановится в двух случаях, и они дают разные сообщения. Если Python на
машине нет вовсе, ставить `uv` нечем — тогда нужна одна из команд ниже. Если
Python есть, но `pip` не смог поставить `uv` (обычно нет доступа к индексу
пакетов или перед ним прокси), повторять ту же команду руками бессмысленно:
загрузчик так и скажет и предложит попросить установку централизованно.

Без прав администратора:

```cmd
py -3.12 -m pip install --user uv
```

С правами администратора:

```cmd
winget install --source winget -e --id astral-sh.uv
```

`--source winget` обязателен: без него winget сначала идёт в источник `msstore`
и на машине с корпоративным перехватом TLS падает с
`0x8a15005e : The server certificate did not match any of the expected values`.

После установки заново запустите `loader.bat`. Менять `PATH` вручную не нужно:
`pip install --user` кладёт `uv.exe` в каталог пользовательских скриптов Python,
которого на `PATH` обычно нет, и `loader.bat` ищет его там сам.

При необходимости задайте пользователя и пароль ClickHouse перед запуском:

```cmd
set CLICKHOUSE_USER=<user>
set CLICKHOUSE_PASSWORD=<password>
loader.bat
```

Если используется secure-подключение с клиентскими сертификатами, укажите в UI
Windows-пути к сертификату и ключу, например:

```text
C:\Users\<username>\tsh\clickhouse-prod.crt
C:\Users\<username>\tsh\clickhouse-prod.key
```

## Ручной запуск и диагностика

Ручные команды нужны только для диагностики, если `loader.bat` завершился с
ошибкой.

Проверьте, что `uv` доступен:

```cmd
uv --version
```

Поставьте окружение из локфайла:

```cmd
uv sync --locked --extra dev
```

Если `uv sync --locked` отказывается работать, потому что локфайл разошёлся с
`pyproject.toml`, пересоберите его — но помните, что это меняет версии библиотек
и обнуляет сравнимость с предыдущими прогонами:

```cmd
uv lock
```

Проверьте, что основные библиотеки доступны:

```cmd
.venv\Scripts\python.exe -c "import streamlit, pandas, clickhouse_connect; print('dependencies OK')"
```

Запустите приложение вручную — тем же путём, которым его запускает `loader.bat`
(модуль сам выберет свободный порт и напечатает версию копии):

```cmd
set PYTHONPATH=%CD%\src
.venv\Scripts\python.exe -m csv_click.launcher
```

Если нужно обойти и модуль, например задать свой порт:

```cmd
set PYTHONPATH=%CD%\src
.venv\Scripts\python.exe -m streamlit run src\csv_click\app.py --server.address 127.0.0.1 --server.port 8600
```

## Как пользоваться

Приложение ведёт по шагам сверху вниз: следующий блок появляется, только когда
подтверждён предыдущий. Порядок пропустить нельзя.

**1. Прочитать файл.** Указать путь к CSV в поле `CSV path`, выбрать разделитель
(`,`, `;`, `\t`, `|` или `custom`) и кодировку (`utf_8`, `cp1251`,
`windows-1251`, `utf-8-sig` или `custom`), затем нажать `Read CSV`. Режим
`Fast sample` смотрит первые 100 000 строк и решает быстро; `Full scan` читает
файл целиком — дольше, но типы выбираются по всем данным.

Чтобы взять другой файл, нажать `Stop read CSV / choose another file`.

**2. Проверить колонки** — блок `Column mapping`. Здесь задаётся имя колонки в
ClickHouse (`target_name`) и то, грузить ли её вообще (`include`). Подтвердить
кнопкой `Apply column mapping`.

**3. Проверить типы** — блок `Type review`. Приложение уже выбрало тип каждой
колонки и в столбце `notes` объяснило, почему тип шире ожидаемого или почему
колонка осталась текстом. Здесь же можно поменять `final_type`, обернуть в
`Nullable` или задать свой тип в `custom_type`. Подтвердить кнопкой
`Apply types`.

**4. Заполнить параметры ClickHouse и загрузки.** Обязательны `Database`,
`Distributed table name`, `Cluster`, `ORDER BY` и `Distributed sharding key` —
последние два выбираются из колонок файла. `PARTITION BY (optional)` — по
желанию. Из остального стоит знать:

- `Batch size` — сколько строк читать за раз, по умолчанию `100_000`;
- `Max insert payload, MB` — предел одного запроса, по умолчанию `16`.
  Приложение намеренно режет на 10% ниже введённого
  (`INSERT_PAYLOAD_SAFETY_RATIO`), чтобы остаться под лимитом HTTP-прокси, то
  есть фактическая граница — `14.4` MB. Действующее значение печатается строкой
  `Load settings` и сохраняется в записи о прогоне;
- `Load workers` — сколько параллельных вставок; на рабочем контуре пятеро
  быстрее одного;
- `Insert compression` — сжатие тела запроса. По умолчанию `off`, рабочее
  значение `gzip`: на реальном файле оно уменьшило передаваемые байты в 6 раз;
- `Strict preflight validation` — заранее проверить, что все значения
  конвертируются в выбранные типы. Дольше перед началом, зато загрузка не
  падает на середине файла.

Подтвердить кнопкой `Apply parameters`.

**5. Проверить подключение** — `Test connection` выполняет `SELECT 1`.

**6. Посмотреть SQL** — `Preview DDL` печатает DDL обеих таблиц и ничего не
создаёт.

**7. Загрузить** — `Create tables and load` создаёт таблицы и грузит данные.

Загрузка идёт в фоне, и страница ей не мешает: случайный клик или обновление
страницы (F5) её не убивают. Пока она идёт, на экране раз в секунду
обновляются текущая фаза, полоса прогресса по прочитанным байтам файла
(чтение опережает подтверждённые вставки), число вставленных строк и хвост
лога. Кнопка `Cancel load` останавливает загрузку: блоки, уже ушедшие на
сервер, доедут и будут посчитаны, нового на сервер не уйдёт. Если к моменту
отмены или сбоя подтверждённые блоки уже есть, таблицы остаются с данными — их
надо удалить вручную перед повторной заливкой; если нет — пара таблиц
удаляется как пустая. Итог — успех, ошибка или отмена, судьба таблиц и путь к
записи прогона — остаётся на экране после любых перерисовок, пока не начата
новая загрузка. Вторая загрузка при живой первой не стартует.

Каждый прогон пишет JSON-запись в `~/.csv_click/runs/`: настройки, счётчики
всех стадий, производные приборы (`worker_occupancy`,
`server_share_of_insert`, `producer_unattributed_s`) и блок `tables` с судьбой
таблиц (`created`, `not_created`, `kept_with_data`, `dropped_as_empty`,
`cleanup_failed`).

## Что создает приложение

Если указать распределенную таблицу `my_table`, приложение создаст:

- локальную таблицу `my_table_local`;
- распределенную таблицу `my_table`.

Локальная таблица создается как:

```sql
ENGINE = ReplicatedMergeTree('/clickhouse/tables/{shard}/<database>/<table>', '{replica}')
ORDER BY <ORDER BY>
```

Если заполнен `PARTITION BY`, он будет добавлен в DDL локальной таблицы.

Распределенная таблица создается как:

```sql
ENGINE = Distributed('<cluster>', '<database>', '<local_table>', <sharding_key>)
```

Перед созданием приложение проверяет через `clusterAllReplicas(system.tables)`,
что ни локальная, ни распределенная целевая таблица еще не существуют. Если
хотя бы одна из них уже есть, создание и загрузка блокируются.

## Правила обработки CSV

- Заголовок CSV обязателен.
- Имена колонок нормализуются под ClickHouse identifier:
  - приводятся к нижнему регистру;
  - неподходящие символы заменяются на `_`;
  - повторяющиеся `_` схлопываются;
  - если имя начинается с цифры, добавляется префикс `col_`.
- Если после нормализации появляются дубли колонок, анализ CSV завершается
  ошибкой.
- Пустые значения приводят к выбору `Nullable(...)` при автоопределении схемы.
- Поддерживаемые итоговые типы, и `Nullable(...)` для каждого из них:
  - `String`, `Int64`, `UInt64`, `Float64`;
  - `Decimal(38, 0)`, `Decimal(76, 0)` — целые, не влезающие в 64 бита;
  - `Decimal(18, 2)`, `Decimal(38, 2)`, `Decimal(76, 2)`, `Decimal(38, 10)`,
    `Decimal(76, 10)`;
  - `Date`, `Date32`, `DateTime`, `Bool`.

  Тип выбирается по фактическим данным колонки, а не по её виду: сумма с 20
  цифрами получит `Decimal` шире, чем `Decimal(18, 2)`, год рождения 1950 —
  `Date32` вместо `Date` (тот начинается с 1970-го), а значение, которое не
  вмещает ни один числовой тип, останется `String`. Причина каждого такого
  решения написана в столбце `notes`.

## Проверка перед загрузкой

При включенном `Strict preflight validation` приложение до создания таблиц и
загрузки:

- читает CSV теми же чанками;
- применяет выбранные маппинги колонок;
- проверяет конвертацию значений в выбранные типы ClickHouse;
- формирует bounded `JSONEachRow` payload для проверки сериализации и лимита размера insert request.

Это увеличивает время перед загрузкой, но снижает риск создать таблицу и затем
упасть на несовместимом значении в середине файла.

## Проверки разработки

Запустить тесты (только из корня репозитория — часть тестов читает файлы по
относительным путям):

```bash
uv run --locked --extra dev pytest
```

`--locked` здесь не формальность: без него `uv run` может перерешать окружение и
переписать `uv.lock`, то есть та самая команда, которой проверяют код, тихо
сдвинет версии, зафиксированные ради сравнимости прогонов.
