| | значение |
|---|---|
| продюсер занят | 240,9 с из 244,3 стенных = **98,6%** |
| простой продюсера | 0,59 с |
| занятость 5 воркеров | **29,9%** |
| сервер | 189,5 с суммой = 52,3% времени вставки |
| стадии продюсера | чтение 100,6 · сериализация 87,0 · конвертация 53,3 |

**Следствие, которое нельзя игнорировать:** параллельные продюсеры отвергались

## 4. Что делать дальше

### Часть C эргономики — следующая по плану оператора

Оператор выбрал порядок A → B → C. C самая крупная: отменяемая загрузка требует
унести продюсера с потока Streamlit.

1. **Загрузку нельзя отменить, rerun её убивает.** Случайный клик убивает часовую
   заливку. Продюсер живёт на потоке скрипта; любой `st.*` может бросить
   `RerunException` — отсюда троттлинг `LOAD_UI_MIN_INTERVAL_S`.
2. **Прогресс-бар мёртв для файлов больше 50 МБ**: считать долю по прочитанным
   байтам, общее число строк неизвестно.
3. **Итог загрузки исчезает после перерисовки.** Поля 0b/8a видны только в
   JSON-записи прогона.
4. **Запись прогона не говорит, что стало с таблицами.** Стало важнее после
   `514466c`: теперь два исхода — «удалены» и «оставлены с данными», — и оператор
   из присланного файла их не различит.
5. **Производные приборы 0b не попадают в запись.** `write_run_record` пишет
   только `server_share`, а он при нескольких воркерах всегда `null`.
   `worker_occupancy` и `server_share_of_insert` приходилось считать вручную по
   присланному файлу. Три строки правки.

### Найдено по пути, не сделано

6. **`PARTITION BY` и имя таблицы теряются** тем же способом, что закрытый п.1
   фазы 7: `st.text_input` без `key=`. Пропущенная перерисовка — и таблица
   создаётся без партиционирования, молча. Есть чип-задача.
7. **`_first_bad_value` называет не ту строку.** При отказе конвертации сообщение
   указывает на соседнюю ИСПРАВНУЮ строку: пробует значение другим путём, чем
   загрузка. Найдено дважды разными ревью.

### Блокеры фазы 6

8. Узкие int сериализуются как `'1.0'`.
9. `Nullable(LowCardinality())` невалиден — чинить обёртку системно, так же
   ломаются `Array` и `Map`.
10. Мёртвый код — последним (`ponytail:ponytail-review`).

## 5. Метод: что реально ловит дефекты

**Зелёные тесты тут НЕ означают работающий код.** За эту сессию состязательное
ревью нашло **13 дефектов в моих же правках**; тесты — ни одного. В каждом из
семи раундов ревью находило что-то, включая внесённые мной регрессии против HEAD.

1. **Тест первым, факт снят исполнением.** Сначала прогнать код и посмотреть, что
   он делает, потом писать ожидание. Дважды моё ожидание было неверным, а код прав.
2. **Мутационная проверка скриптом.** Мутация ловится ПАДЕНИЕМ теста («N failed»,
   не «N error»); эквивалентные мутации остаются зелёными. Мутация, которую тест
   не убил, — вопрос, а не приговор: трижды это означало лишнюю строку в коде
   (поведение уже обеспечивала библиотека), и строка удалялась.
3. **Состязательное ревью через `Workflow`:** 3–5 линз, у каждой свой скептик,
   отдельная линза `regression_of_this_diff` со сравнением против
   `git show HEAD:файл`. Ревьюить надо ФИНАЛЬНЫЙ диф: смена решения после ревью
   обнуляет вердикт. Каждую находку проверять самому — скептики ошибались в
   деталях.
4. **Отвергнутое решение закреплять мутацией.** Мутация, возвращающая отвергнутую
   версию, не даёт ей вернуться тихо. Так закреплены: `index=` в тождестве
   виджета, предикат nan по `float()`, шаг из флагов подтверждения, округлённая
   граница Decimal.
5. **Проверять не имя типа, а что доедет до сервера.** Тест, сверявший только
   выбранный тип, пропустил дефект, при котором тип выбирался, а файл не
   загружался. Теперь тесты инференса прогоняют строгий префлайт и смотрят
   payload.
6. **Вводя новый тип ClickHouse, сначала зонд на путь загрузки.** `Date32` попал
   в редактор и в инференс без ветки в конвертерах — валидация на такой колонке
   не проверяла ничего. На `Decimal(38, 0)` порядок был обратный, и дефекта не
   возникло.

## 6. Ловушки, каждая стоила времени

**Мутационный скрипт врёт двумя способами.** `.pyc` валидируется по паре
(mtime, size): два мутанта ОДНОГО размера, записанные подряд, исполняют байткод
друг друга. И: мутация во втором файле доживает до следующей итерации, если не
восстанавливать ВСЕ тронутые файлы. Лечение в каждом скрипте: удалять
`__pycache__`, передавать `PYTHONDONTWRITEBYTECODE=1`, восстанавливать все файлы
перед каждой мутацией. Признак подмены: падает тест, к применённой мутации не
относящийся. **Не запускать мутации, пока идёт ревью** — агент видел временно
испорченные файлы и получил недостоверные замеры.

**Тест, где особое значение стоит ПОСЛЕДНИМ, не держит накопление.** Трижды
мутация «помнить только последнее» выживала — у дат, у целых, у шагов. Лечение:
тест, где особое значение стоит первым или в середине.

**Streamlit 1.58** (измерено, см. `memory/csv-click-streamlit-traps.md`):
`index=` входит в тождество виджета; `on_change` срабатывает только на ИЗМЕНЕНИЕ;
значение вне `options` гасится молча; состояние виджета живёт, только пока он
рисуется; `AppTest.session_state` не имеет `.get()`; `Expander` не отдаёт
`expanded` — только через `node.proto`; слот `st.empty()` может принять expander
позже в том же прогоне.

**Решать до того, как случилось решающее.** Три дефекта части B — один корень:
строка пути и подсказки рисовались до блоков, которые меняют состояние. Лечение:
занять место, заполнить в `finally`, а «где мы» выводить из отрисованного.

**`decimal` округляет через контекст.** `Decimal(10) ** 38 - 1` при prec=28 даёт
`10**38`, и унарный минус тоже округляет. Границы — целочисленной арифметикой,
сравнение `Decimal` с `int` точное.

**Инструменты.** `subprocess(text=True)` декодирует cp1251 и падает на кириллице
— передавать `encoding="utf-8"`. PowerShell ломает `python -c` с кавычками и
многострочные here-string — писать скрипт файлом. `write_text` на Windows сам
добавляет CRLF: своё `\r\n` даёт `\r\r\n`, и cmd на таком не находит метку.
Файлы репозитория править ТОЛЬКО Write/Edit или питоном. Коммиты только
`git commit -F файл`.

## 7. Окружение и процесс

- **Оператор работает с `main` через PR** на рабочем ПК (единственном с доступом
  к кластеру): ветка → push → он делает PR и мержит → тестирует. Пушить по
  просьбе; в этой сессии просьба была дана и исполнена трижды.
- Личный ПК: кластера нет, `tp17.wb-bank.ru` не резолвится. Всё проверяется
  локально: фейки, `AppTest`, локальные сокеты.
- Записи прогонов: `~/.csv_click/runs/<utc>-<таблица>.json`, оператор присылает
  файлами.
- **Пользователи приложения:** 2–10 аналитиков отдела, не программисты, Windows
  без прав администратора, получают проект через `git clone`. Есть ли у них
  Python — неизвестно. Спотыкаются, по словам оператора, на установке, на шагах
  интерфейса и на самой заливке; с подключением к ClickHouse справляются.
- Репозиторий ПУБЛИЧНЫЙ: персональных данных не добавлять.
- Рабочее значение сжатия — `gzip` (в форме по умолчанию `off`).
