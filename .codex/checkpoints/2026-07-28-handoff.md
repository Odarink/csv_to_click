## 1. ИТОГ ПО СКОРОСТИ: 5,3×, работа закрыта

Один и тот же файл 5,5 ГБ / 499 992 014 строк, рабочий контур оператора:

| Прогон | Время | Против ночного |
|---|---:|---:|
| Без сжатия, ночь (после Arrow) | 1949 с | 1,00× |
| Без сжатия, лучший дневной | 818 с | 2,38× |
| gzip в продюсере | 530 с | 3,68× |
| **gzip в воркерах — итог** | **369,6 с** | **5,30×** |

**1 358 911 строк/с.** Сжатие на реальных данных **6,08×** (9,54 → 1,57 ГБ).
Сессия начиналась с 618 690 строк/с; исходная задача была «1 ГБ за 45 минут».

**Почему закрыта, арифметикой.** Финальный прогон: продюсер занят 79%
(чтение 128 с + конвертация 59 с + сериализация 103 с = 291 с), воркеры заняты
81%, сервер 17% времени вставки, провод несёт 1,57 ГБ при 4,26 МБ/с = 368 с —
ровно всё стенное время. Продюсер (291 с) и провод (368 с) СОШЛИСЬ: перекоса,
который можно выправить, больше нет.

**Отвергнуто с ценой — НЕ переоткрывать:**

- *Параллельные продюсеры*: опустят пол с 291 до 168 с, но провод требует
  ~365 с. Выигрыш ноль. (Отдельно: потоки поверх `to_json` мертвы — GIL не
  отпускается, 1,01×; Arrow отпускает, 2,25×; zlib отпускает, 4,5× — но всё
  это уже использовано.)
- *TabSeparated поверх gzip*: gzip уже съел повторяющиеся имена полей JSON,
  экономия не 1,82×, а 20–25% (~290 с), и там упрётся продюсер. Цена — новый
  формат с риском тихой порчи и БЕЗ эталона для сверки. Плохой размен.
- *zstd*: отвергнут контуром дважды — `unsupported compression method zstd`
  от того, что стоит ПЕРЕД ClickHouse. *lz4*: жмёт вдвое хуже gzip, не пробовали
  и незачем. *gzip уровень 9*: 3,40× против 3,32× при 7 МБ/с. Нет.
- *Больше воркеров*: потолок на АГРЕГАТЕ — 5 соединений дают 1,35× от одного.
  `load_workers` — почти мёртвая ручка на этом контуре.
- *SO_SNDBUF/BDP*: драйвер прибивает 256 КиБ, использовалось 3–7%. Окно
  отправителя не ограничивало НИ ОДИН прогон.

**Факт про контур, который объясняет будущие «регрессии»:** его ёмкость гуляет
по времени суток в **2,38×** (11,65 МБ/с в 16:46 против 4,89 МБ/с в 22:08, одна
подсеть). Любое сравнение «до/после» — только парными прогонами в один час.
Прогон 5 выглядел регрессией Arrow ровно из-за этого; код был оправдан шестью
гипотезами со скептиками (раздел 4.0-трижды старой передачи).

## 3. Что делать дальше — фаза 7, тихие порчи данных

Скорость больше не аргумент; здесь данные портятся или теряются. По убыванию
тихости (тихое — раньше):

1. **`ORDER BY` и ключ шардирования молча сбрасываются на первую колонку** при
   любой перерисовке: `st.selectbox` без `key=` в `app.py`. Оператор выбирает
   ключ — таблица создаётся с другим. Дёшево, брать первым. (Инвентарь, фаза 7.)
2. **Точность `Decimal` не отслеживается**: `Decimal(18,2)` выбирается
   значениям, которым нужно 22+ цифры. Инференс в `schema.py` уже считает
   `max_decimal_scale`, но не precision.
3. **Даты**: 1900/1950 переполняют `Date` (тип надо расширять до Date32 или
   String с пометкой); офсет часового пояса инферится в наивный `DateTime`
   (путь загрузки падает громко — фаза 3, — но ИНФЕРЕНС всё ещё выбирает
   DateTime такой колонке).
4. **Автоудаление ОБЕИХ таблиц при любом сбое загрузки**
   (`_cleanup_after_failed_load` в `app.py`): один транзиентный 5xx на 900-м
   блоке из 1000 уничтожает всё залитое. 8a закрыла только случай «загрузка
   прошла, упал отчёт».
5. **Нет проверки величины**: 20+ значащих цифр → `UInt64` → переполнение
   роняет загрузку посреди файла. Падает громко, поэтому последним.

Затем фаза 8 (эргономика): загрузку нельзя отменить, rerun её убивает; после
rerun экран пуст (поля 0b/8a видны только в JSON-записи); запись не говорит,
отработала ли чистка; прогресс-бар мёртв >50 МБ (считать по байтам).
Блокеры фазы 6: узкие int сериализуются `'1.0'`; `Nullable(LowCardinality())`
невалиден (чинить обёртку системно — ломаются и `Array`, `Map`). README врёт
про интерфейс. Мёртвый код — последним (`ponytail:ponytail-review`).

## 4. Метод: что реально ловит дефекты (проверено многократно)

**Зелёные тесты тут НЕ означают работающий код.** За сессию инструменты нашли
6 моих собственных дефектов, тесты — ноль из них.

1. **Мутационная проверка скриптом, с таймаутом.** Обязательно: мутация
   ловится ПАДЕНИЕМ теста, не ошибкой импорта («1 failed», не «1 error» —
   скрипт различает сам); ЭКВИВАЛЕНТНЫЕ мутации (снять оптимизацию — тесты
   обязаны остаться зелёными, иначе тест держит текст, а не поведение).
   Образцы скриптов — в истории сессии; писать свой на каждую фазу.
2. **Состязательное ревью через `Workflow`**: 5–7 независимых линз, у каждой
   СВОЙ скептик, отдельная линза на диф самих правок, вердикт
   `regression_of_this_diff` через сравнение с `git show HEAD:файл`.
   Одиночный ревьюер на том же дифе не находил ничего.
3. **Дифференциальный фаззер и ревью ловят РАЗНОЕ, нужны оба.** Фаззер нашёл
   неэкранированные имена колонок за 14 итераций; ревью нашло падение на
   колонке >2 ГиБ, которую фаззер не генерировал. Фаззер с фиксированным
   семенем забран в тесты.
4. **Фейк обязан повторять ПОВЕДЕНИЕ библиотеки на аргументе, не форму
   возврата.** Дефект `off`→`Content-Encoding` стоил двух прогонов оператора:
   фейк принимал любой `compression`, драйвер делает заголовок из любой
   непустой строки. И проверять то значение, которое РЕАЛЬНО ходит по пути
   (приложение передаёт `"off"`, тесты передавали `None`).
5. **Гоночный тест проходит по случайности до первого ускорения.** Мгновенный
   фейк → всё успевает до отмены → `blocks_unconfirmed` не проверяется.
   Лечение: `SlowClient` со сном, детерминированное окно.
6. **Новое поле умеет врать в обе стороны сразу** (`source_fully_read`).
   Лечение: второе поле + докстринга о том, чего поле НЕ обещает.
   И проверять ДОСТИЖИМОСТЬ сообщений оператору (одно оказалось мёртвым кодом).

**Ловушки инструментов** (каждая стоила времени):

- `Set-Content -Encoding utf8` пишет BOM. Файлы править ТОЛЬКО Write/Edit или
  питоном. Коммиты только `git commit -F файл` (или `-F -` с heredoc БЕЗ
  кириллических кавычек внутри).
- Bash-heredoc с кириллицей/кавычками портит текст и дважды протаскивал
  управляющий символ 0x01 в исходник. Для правок файлов — Write/Edit.
- `$` в PowerShell-регулярке не совпадает при CRLF; замена молча не
  применяется — проверять, что файл изменился.
- Ловушки библиотек — раздел 5 старой передачи (пустая сводка драйвера,
  `RecentlyUsedContainer`, LifoQueue, `Thread._stop`, `to_json` и inf,
  `.dt.strftime` и год без нулей).

## 5. Окружение и процесс

- **Оператор работает с `main` на рабочем ПК** (единственном с доступом к
  кластеру): ветка → push → оператор делает PR и мержит → тестирует. Пушить
  только по его просьбе.
- Личный ПК: кластера нет, `tp17.wb-bank.ru` не резолвится. Всё проверяется
  локально; фейки и локальные сокеты.
- Записи прогонов: `~/.csv_click/runs/<utc>-<таблица>.json`, оператор
  присылает файлами. Поля 0b читать так: `worker_occupancy`≈1 + большой
  `producer_stall_s` = узкое место провод/сервер; occupancy низкая = продюсер.
- Репозиторий ПУБЛИЧНЫЙ: персональных данных не добавлять.
- Настройка сжатия: `Insert compression` в форме, по умолчанию `off`,
  рабочее значение — `gzip`. В `~/.csv_click/settings.json` поле
  `insert_compression`.
